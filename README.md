## CSS Architecture

I organized my CSS using cascade layers:

`tokens → base → layout → components → utilities`

Each layer has a different purpose:

| Layer      | Purpose                                 |
| ---------- | --------------------------------------- |
| Tokens     | Defines reusable design values.         |
| Base       | Styles basic HTML elements.             |
| Layout     | Organizes page structure.               |
| Components | Styles reusable interface elements.     |
| Utilities  | Provides small reusable helper classes. |

This architecture helps me keep my styles organized and makes them easier to update.

## Unit 4: CSS Grid and Responsive Layouts

In Unit 4, I practiced advanced CSS layout techniques, including CSS Grid, Flexbox, Subgrid, Container Queries, and Sticky Positioning.

### Editorial Layout

I created a page with a main article and a sidebar.

I used:

- `grid-template-areas` — Gives names to different sections.
- `grid-area` — Places elements in those sections.
- `grid-template-columns` — Controls the column widths.
- `gap` — Adds spacing between sections.
- `@media` — Changes the layout based on screen width.

On mobile screens, the article appears above the sidebar.

On desktop screens, the article and sidebar appear next to each other.

I also used Flexbox to arrange the navigation links.

### Responsive Cards

I created six cards that automatically change their arrangement depending on the available space.

I used:

- `repeat()` — Repeats the column pattern.
- `auto-fit` — Fits as many columns as possible.
- `minmax()` — Controls minimum and maximum column widths.
- `min()` — Prevents columns from becoming wider than their container.
- `1fr` — Allows columns to grow equally.

My Grid uses:

```css
grid-template-columns: repeat(auto-fit, minmax(min(240px, 100%), 1fr));
```

This allows the cards to change their arrangement depending on the available space.

### Flexbox and Card Alignment

I used Flexbox to place the image placeholder above the text.

I also wanted the **Read more** links to stay at the bottom of each card.

To do this, I used:

- `display: flex` — Activates Flexbox.
- `flex-direction: column` — Arranges elements vertically.
- `flex: 1` — Makes the content area grow.
- `margin-block-start: auto` — Pushes the link to the bottom.
- `flex-shrink: 0` — Keeps the placeholder at its fixed height.

I chose this approach because the links stay aligned even when the cards have different amounts of text.

## Unit 5: Typography Tokens and Web Fonts

In Unit 5, I created a reusable typography system for my portfolio.

My goal was to make the typography consistent, responsive, and easier to maintain throughout my website.

### Modular Typography Scale

I created seven typography scale tokens using a ratio of approximately 1.25.

My base font size is 16px.

| Token             | Minimum Size | Maximum Size |
| ----------------- | ------------ | ------------ |
| `--font-size-xs`  | 10.24px      | 10.24px      |
| `--font-size-sm`  | 12.8px       | 12.8px       |
| `--font-size-md`  | 16px         | 16px         |
| `--font-size-lg`  | 18px         | 25px         |
| `--font-size-xl`  | 22.5px       | 31.25px      |
| `--font-size-2xl` | 28.125px     | 39.06px      |
| `--font-size-3xl` | 35.16px      | 48.83px      |

I used fixed sizes for smaller text and fluid sizes for larger text.

The larger sizes maintain approximately the same modular ratio, while the relationship between fixed body text and fluid headings changes with the viewport.

### Fluid Typography

I used `clamp()` to create responsive font sizes without needing multiple media queries.

The function accepts three values:

```css
clamp(minimum, preferred, maximum)
```

For example:

```css
--font-size-lg: clamp(18px, 16.158px + 0.614vw, 25px);
```

- The minimum prevents the text from becoming too small.
- The preferred value allows the text to grow with the viewport.
- The maximum prevents the text from becoming too large.

I calculated my fluid typography using a minimum viewport width of 300px and a maximum viewport width of 1440px.

I used a slope and an intercept to calculate the preferred value.

```text
Slope = (maximum font size - minimum font size)
        / (maximum viewport - minimum viewport)

Intercept = minimum font size - slope × minimum viewport
```

I learned that fluid typography allows headings to adjust gradually as the screen size changes.

### Fixed vs. Fluid Typography

I decided to use fixed font sizes for body text and captions because I wanted them to remain consistent.

I used fluid font sizes for headings because larger text needs more flexibility on different screen sizes.

This allows me to create a responsive visual hierarchy without writing additional media queries.

### Line-Height Tokens

I created three reusable line-height tokens:

```css
--line-height-tight: 1.2;
--line-height-normal: 1.5;
--line-height-relaxed: 2;
```

| Token                   | Purpose                            |
| ----------------------- | ---------------------------------- |
| `--line-height-tight`   | Headings                           |
| `--line-height-normal`  | Regular body text                  |
| `--line-height-relaxed` | Text that needs additional spacing |

I learned that unitless line heights adjust automatically based on the element's font size.

### Semantic Typography Tokens

I created semantic tokens that reference my modular scale.

```css
--font-size-caption: var(--font-size-sm);
--font-size-body: var(--font-size-md);
--font-size-heading-sm: var(--font-size-lg);
--font-size-heading-lg: var(--font-size-2xl);
--font-size-display: var(--font-size-3xl);
```

| Semantic Token           | Purpose                               |
| ------------------------ | ------------------------------------- |
| `--font-size-caption`    | Captions and supplementary text       |
| `--font-size-body`       | Paragraphs and regular interface text |
| `--font-size-heading-sm` | Smaller headings                      |
| `--font-size-heading-lg` | Section headings                      |
| `--font-size-display`    | Main page headings                    |

### Two-Layer Token System

I learned the difference between scale tokens and semantic tokens.

Scale tokens define the actual font sizes.

Semantic tokens describe how those sizes should be used.

For example:

```css
--font-size-md: 16px;
--font-size-body: var(--font-size-md);
```

Instead of applying a specific size directly to a paragraph, I can use a token that describes its purpose.

This makes the typography easier to maintain because I can change the relationship between a semantic token and a scale token without updating every component.

### Web Fonts

I added two custom fonts using Google Fonts.

- **Koh Santepheap** — Used for headings.
- **Montserrat** — Used for body text.

I created font-family tokens:

```css
--font-family-sans: Helvetica, Arial, sans-serif;
--font-family-mono: monospace;
--font-family-heading: "Koh Santepheap", Georgia, serif;
--font-family-body: "Montserrat", var(--font-family-sans);
```

The fallback fonts allow the browser to display text even if the custom fonts are unavailable.

### Font Display

I used `display=swap` in my Google Fonts import.

This allows the browser to display a fallback font while the custom font is loading.

Once the custom font becomes available, the browser replaces the fallback font.

The benefit is that users can read the content immediately. A possible disadvantage is that the text may shift slightly when the custom font replaces the fallback font.

### Applying Typography to Base Elements

I updated `css/base/elements.css` to use the new semantic typography tokens.

For example:

```css
body {
  font-family: var(--font-family-body);
  font-size: var(--font-size-body);
  line-height: var(--line-height-normal);
}

h1 {
  font-family: var(--font-family-heading);
  font-size: var(--font-size-display);
  line-height: var(--line-height-tight);
}

h2 {
  font-family: var(--font-family-heading);
  font-size: var(--font-size-heading-lg);
  line-height: var(--line-height-tight);
}

h3 {
  font-family: var(--font-family-heading);
  font-size: var(--font-size-heading-sm);
  line-height: var(--line-height-tight);
}
```

I learned that paragraphs, links, and list items can inherit typography from the body instead of repeating the same declarations.

## Build Tool

I used Lightning CSS to bundle and minify my stylesheets.

This tool combines my CSS files into one optimized file.

### How to Run the Build

First, install the dependencies:

```bash
npm install
```

Then run:

```bash
npm run build
```

The build uses this command:

```bash
lightningcss --bundle --minify css/main.css -o dist/styles.css
```

The generated CSS is saved in `dist/styles.css`.
